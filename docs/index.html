History

It started in 5U

The ArdCore began as Darwin Grosse's final project for his master's degree. The pitch was simple: put an Arduino behind a synth panel, give it enough knobs and jacks to be useful, and let people write their own module in C. He released it under his 20 Objects name.

The first version was 5U, for Moog-unit systems like the Synthesizers.com cabinets people call "dotcom". It was DIY in the full sense: you bought a PCB and wired the panel yourself. There was a 5U Output Expander too, which turned the eight DAC pins into eight gate outputs. The OX sketches in this repo still do exactly that.

Dan Snazelle at Snazzy FX then made the eurorack version. The 10HP module came out in 2012 and kept the controls from the 5U panel: two knobs, CV inputs on A2 and A3, a clock input, the DAC output, gates on D0 and D1, and a USB socket for uploading sketches. It sold out and was hard to get hold of for a couple of years after.

Darwin put his sketch library on GitHub the same year and kept adding to it, and other people started writing their own. Away from the ArdCore he worked at Cycling '74 and hosted the Art + Music + Technology podcast. He died in June 2022.

This repo gathers his library, the Snazzy FX sketches and community sets like Ascetic's in one place, and adds some new ones, including ports of VCV Rack modules.

Hardware Reference

The panel

Under the panel it's basically an Arduino. This is what each jack and knob is wired to.

↓ Download panel design (.fpd for Front Panel Express)
Inputs
Knob 1 & Knob 2 (top two knobs)
Read on A0 and A1 with analogRead(), 0 to 1023. Each sketch decides what they do: speed, pitch, depth and so on.
A2 & A3 (CV input jacks)
CV inputs. 0 to 5V reads as 0 to 1023. Sketches use them for 1V/oct pitch, envelopes or any other modulation.
Clock In (trigger/gate jack)
Pin 2, on a hardware interrupt. A rising edge fires the ISR, so clocks, triggers and gates all work. Sketches use it to sync tempo, fire envelopes and step sequencers.
Outputs
DAC Out × 2 (main output jacks)
The main output, for CV or audio. The two jacks carry the same signal, so you get a free mult. The DAC is an 8-bit R-2R ladder on digital pins 5 to 12, which gives 256 steps between 0 and 5V.
D0 & D1 (digital output jacks)
Pins 3 and 4. They're either 0V or 5V, so use them for gates and triggers: clock out, end of cycle, rhythms.
Output Expander
The expander reads the eight DAC pins as eight separate gates. You get one or the other, the DAC voltage or the eight gates, because they share the same pins. Expander sketches start with OX.
DSP Techniques

Integer math on 8-bit hardware

The ATmega328P runs at 16MHz, has 2KB of RAM and no FPU. Floats work but they're slow, so most sketches stick to integers. These are the tricks that keep coming up.

Fixed-point scaling
Multiply by an integer, then divide by a power of two. To scale by 0.7, write (long)val * 718L / 1024L. The compiler turns the divide into a shift.
Wavetable lookup
Keep one cycle of the wave in PROGMEM as 256 bytes and step through it with a phase accumulator. The same few lines cover everything from slow LFOs to audio rate.
Direct port writes
digitalWrite() sets one pin at a time and is slow. Writing PORTB and PORTD directly sets all eight DAC bits in a couple of writes, which you need at audio rate.
LFSR noise
XOR a few tapped bits, shift, repeat. A 16-bit LFSR runs through 65535 values before it repeats, and the whole state fits in one unsigned int.
Overflow arithmetic
Two 10-bit readings multiplied together overflow an int. Cast one side to long first, then divide and cast back.
Envelope state machines
Attack, decay and release are integer ramps. Add the rate each pass through loop(), keep a variable for the current stage, and write the level to the DAC.
Clock interrupts
Attach an interrupt to pin 2 on the rising edge. The ISR only sets a flag; loop() checks it. Keep analogRead() and DAC writes out of the ISR.
Chaotic maps
Logistic maps, shift registers with nonlinear feedback, neuron models. They need very little state and they're fine in integer math.
VCV Rack → ArdCore

Port your favorite modules

SquidAxon, Genie, Rungler and AlgoVCO came over from VCV Rack this way. Here are the steps if you want to try one.

Step 1
Map I/O
A VCV module can have as many knobs and jacks as it likes. The ArdCore has two knobs, two CV ins, a clock in, the DAC and two gate outs, so decide what goes where first. Chaos generators and oscillators are the easiest to port because they don't need many inputs.
Step 2
Kill the floats
Swap floats for integers. A 0.0 to 1.0 range becomes 0 to 1023, fractions become multiply-then-divide, and anything that might overflow gets cast to long.
(long)val * 718L / 1024L // ≈ val × 0.7
Step 3
Watch the RAM
You have 2KB and the Arduino core uses about 500 bytes of it. Put lookup tables in PROGMEM: a 256-byte wavetable left in RAM takes an eighth of it.
Step 4
Document everything
Put an I/O header at the top, say how the algorithm works, and draw an ASCII diagram if it helps. The template in templates/ has the layout.
cp templates/VCV_PORT_TEMPLATE.ino my_port/
macOS Setup

Compiling on a Mac

How to build sketches and get them onto the module with arduino-cli.

Step 1: install the toolchain
Homebrew + arduino-cli
Install Homebrew if you don't have it, then arduino-cli, Arduino's own command-line tool.
Install 
# Install Homebrew (skip if you already have it)
$ /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install arduino-cli
$ brew install arduino-cli

# Install the AVR core (ATmega328P lives here)
$ arduino-cli core install arduino:avr
The AVR core is about 150MB.
Step 2: clone and check
Clone the repo and compile everything
verify-all.sh compiles every sketch for the Arduino Nano and skips anything listed in scripts/verify-ignore.txt.
Verify 
# Clone the repo
$ git clone https://github.com/mamonulabs/ard-glow.git
$ cd ard-glow

# Run the batch compile check
$ ./scripts/verify-all.sh

  ArdCore Sketch Compiler — board: arduino:avr:nano

  PASS  official/AC01_Template/AC01_Template.ino
  PASS  official/AC02_Quantizer/AC02_Quantizer.ino
  …
  SKIP  community/asct/ASCTard005_LFO/ASCTard005_LFO.ino

  Results: 135 passed, 0 failed, 15 skipped
Add --verbose to see the compiler errors for anything that fails.
Step 3: build and upload one sketch
Upload to the ArdCore
Plug the ArdCore in over USB, find its port, and add -u -p to the compile command.
Compile and upload 
# Compile only (no hardware needed)
$ arduino-cli compile --fqbn arduino:avr:nano \
    official/AC07_Sequencer/AC07_Sequencer.ino

Sketch uses 3,842 bytes (12%) of program storage space.
Global variables use 134 bytes (6%) of dynamic memory.

# Find your serial port
$ arduino-cli board list

Port         Protocol Type Board Name  FQBN
/dev/cu.usbserial-1420 serial   Serial Port (USB) …

# Compile + upload (ATmega328P with old bootloader)
$ arduino-cli compile -u -p /dev/cu.usbserial-1420 \
    --fqbn arduino:avr:nano:cpu=atmega328old \
    official/AC07_Sequencer/AC07_Sequencer.ino
Most ArdCores have the old bootloader, hence cpu=atmega328old. If the upload fails, try it without.
Or use the Arduino IDE
Arduino IDE
Set the board to Arduino Nano and the processor to ATmega328P (Old Bootloader), then open the .ino file.
Install the IDE (optional) 
# Install Arduino IDE via Homebrew Cask
$ brew install --cask arduino-ide

# Or download from https://www.arduino.cc/en/software
The CLI is quicker for building lots of sketches. The IDE is easier for editing and watching the serial monitor.
